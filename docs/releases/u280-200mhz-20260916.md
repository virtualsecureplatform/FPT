# U280 200 MHz hardware-validated baseline — 2026-09-16

This experimental release preserves the first fully passing window-reset trial.
It is a routable, nonzero-hardware-regression-tested baseline, not yet a
reproduction of the paper's sustained performance or a complete cryptographic
correctness validation.

## Design and acceptance

Blind rotation plus sample extraction, paper Set II arithmetic, 16 contexts,
630-dimensional input and 1024-dimensional output. Identity key switching (IKS)
is NOT included. The design uses MSB-first window alignment, selective metadata
reset removal, lane-local coefficient/key controls, bank-local accumulator
initialization, and protected local rolling enables. Options remain opt-in.

- Target: U280, xilinx_u280_gen3x16_xdma_1_202211_1, Vitis/Vivado 2023.2.
- Kernel clock: 200 MHz (5 ns). Full build finished 2026-09-16 05:01 JST.
- Fully routed, no routing errors; setup WNS and hold slack both 0.000 ns.
- Kernel TNS 0, failing endpoints 0. There is no reported timing margin.
- Post-route DRC: 0 errors/fatal/critical warnings; 9698 warnings, 5 advisories.
- Router timing congestion decreased from 7 to 6; global/short remains 6.
- Synthesized kernel: 527152 LUT, 757398 FF, 5624 DSP, 468 BRAM tiles, 236 URAM.
- All structural gates passed, including 392 unreset metadata bits and 128
  retained write-mask reset bits.

## Validation and measured performance

Common tests 13/13; four variant suites 24/24 each; wide coefficient equivalence
64/64; additional regression 24/24. Numerical checks retain the expected output
checksum and CMUX latency 239 cycles / II 16. The 20852-cycle numerical fixture
uses domainDimension=1 and deliberate output stalls; it is NOT the hardware
latency for all 630 blind-rotation iterations.

hw_emu and physical U280 both passed the 16400-word zero-vector smoke test.
Physical smoke reported no DataMover error. A further 5 warmups and 100 timed
executions passed, with final output verified:

| Host start/wait time, 16-context batch | Microseconds |
| --- | ---: |
| Minimum | 981.753 |
| Median | 985.080 |
| Mean | 986.380 |
| p95 | 998.144 |
| Maximum | 999.076 |

The measured median implies 16.24 results/ms for sequential batches. Timing
excludes initial input/key PCIe transfers and final output readback, includes
XRT dispatch/wait overhead, and is not a device-cycle-counter measurement.
61.568 us/context is an amortized throughput number, not individual latency.
Board remained healthy and idle after 106 executions; FPGA temperature 40 C.
Six nonzero hardware cases subsequently passed all 16400 words bit-for-bit.
The C++-oracle-validated one-step RTL fixture is extended to 630 steps using
zero-key updates or zero-exponent differences. Cases cover nonzero initialized
accumulators with zero keys; a dense nonzero CMUX at key indices 0, 1, 314,
and 629; and a fully populated key stream with only the last mask exponent
nonzero. The active reference changes 14291 words versus initialization.
All cases transferred 80640 key beats without DataMover error. This verifies
nonzero datapath, ordering and key-bank reuse, but is NOT a dense 630-active-step
test with real encrypted ciphertexts and cryptographically generated keys.

The exact RTL reference retains SHA256
`b02dc10d50e4111bd5e4b79993b355942fd58b2d6d758d40bc544901f38f372e`
over little-endian 32-bit output words. `vitis/host/nonzero.cpp` implements the
hardware test; `FPT_BLIND_ROTATE_RESULT_FILE` exports the reference from the
existing numerical regression after all oracle gates pass. This test-only
export was added after synthesis; no synthesized RTL changed.

Hardware counters report 178235 cycles (0.891175 ms at 200 MHz), from core
start until completion is observed, including output drain/backpressure within
that interval. Key-starvation counts were 108–174, while key-bank-blocked counts
were 88751–88821. These counters overlap and must not be added as disjoint
latency components. The data points away from raw HBM key bandwidth as the
dominant bottleneck; bank blocking can simply reflect expected prefetch wait.

The paper (2022/1635, Table 4, Set II) reports 0.74 ms for 12 contexts and
25 PBS/ms with overlapped execution, at 200 MHz; IKS is treated separately.
Our batch is larger and the measurement boundaries differ. Similar normalized
batch times do not establish matching sustained throughput. CMUX II matches
(16) but pipeline latency is 239 versus the paper's 192 cycles.

## Next performance work

Preserve this release as the timing-safe baseline. Hardware counters and the
nonzero regression now establish an initial baseline. Next isolate scheduling,
feedback and output-drain overhead with cycle-level traces and target confirmed
bubbles with opt-in RTL. Raw key-bandwidth expansion is not the first priority
given the very small observed starvation count. Add dense multi-step encrypted
correctness and overlapped end-to-end throughput measurement. Do not remove
timing-protection registers blindly:
the current setup margin is zero. Keep 200 MHz, bitwise correctness, and route
gates; report device cycles, end-to-end latency, and sustained throughput
separately before claiming the paper's 25 PBS/ms.
